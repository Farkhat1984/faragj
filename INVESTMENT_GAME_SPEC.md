# ТЗ: Инвестиционная игра «Time Capital» (рабочее название)

Документ — дизайн и техническое задание новой игры, интегрируемой в существующее приложение (Express + Socket.IO + React SPA). Игра делит инфраструктуру с викториной (`server/src/index.ts`, `client/src/App.tsx`, фазовая машина, room-based emit, админ-токен), но имеет собственный набор фаз, собственный игровой стейт и собственный набор экранов.

---

## 1. Концепция в одном абзаце

Модератор выбирает исторический период (например, 1996 → 2024). У каждого игрока стартовый капитал: **$100 000** и **₸10 000 000**. Каждый раунд — один календарный год. За раунд игрок перераспределяет портфель между классами активов (акции, облигации, депозиты в USD/KZT, недвижимость в Казахстане, золото, кэш, и др.). После закрытия раунда раскрываются реальные доходности этого года + сюрпризные события, портфели пересчитываются с учётом инфляции, происходят случайные шоки. Побеждает не один игрок, а **несколько** — по разным метрикам (макс. доход, лучший Sharpe, минимальная просадка, выживший в худший кризис, лучший диверсификатор).

Главный вызов дизайна — **не дать игрокам читерить хиндсайтом** («просто залью всё в Google в 1998»). Решается комбинацией анонимизации, альтернативной истории и механических ограничений (см. §6).

---

## 2. Почему именно эта механика — обоснование решений

| Проблема | Решение | Почему так |
|---|---|---|
| Игроки знают, что Apple/Google/Amazon = победители | **Codename Mode**: тикеры скрыты, активы показаны как «TECH-A: software company, 12k employees, P/E 28». Идентичность раскрывается в конце игры. | Сохраняет ощущение «инвестирования в неизвестность», как у реального инвестора. |
| Даже скрытые «единороги» распознаются по подсказкам | **Alt-History Modifiers**: при старте каждой игры случайно применяются 2–4 «что если» сценария, ±30% к доходностям конкретных активов | Один и тот же актив в двух разных играх ведёт себя по-разному. Заучивание не работает. |
| «Положу всё в одну акцию и выиграю» | Жёсткий **cap 20%** на один тикер (настраиваемо), плюс **friction**: за раунд можно ребалансировать не более 30% портфеля | Имитация реальных ограничений + наказание за безудержный all-in. |
| Скучно, если ничего не происходит | **Event Cards** — каждый год тянется 1–3 события из колоды (реальные исторические + альтернативные + фейки) | Драматизация без потери реалистичности. |
| «Я просто проверю реальные данные онлайн» | Реальные числа в SQLite + анонимизированные имена + alt-history → даже если игрок угадает компанию, доходность в этой партии может отличаться | Бесполезно гуглить — данные те же, но модификаторы рандомные. |
| Слишком сложно для новичков | **Easy mode** = только 4 класса активов (депозит USD, депозит KZT, золото, индекс S&P 500). **Hard mode** = всё. | Прогрессия сложности. |

## 3. Стек данных — что собирать, откуда

Создаётся **read-only SQLite** база `data/historical.sqlite`. Грузится один раз при старте сервера. Игра не пишет в неё во время раунда.

### 3.1 Таблицы

```sql
-- Годовая инфляция и FX
inflation (year INT PK, country TEXT, cpi_pct REAL)
fx_rates  (year INT PK, usd_kzt_end REAL, usd_kzt_avg REAL)

-- Базовые ставки
risk_free (year INT PK, fed_funds_pct REAL, kz_natbank_pct REAL)

-- Депозиты (агрегаты по рынку)
deposits  (year INT, currency TEXT, term_months INT, rate_pct REAL, PRIMARY KEY(year, currency, term_months))

-- Облигации
bonds (year INT, kind TEXT, maturity_years INT, yield_pct REAL,
       PRIMARY KEY(year, kind, maturity_years))
-- kind: us_treasury, us_corp_aaa, us_corp_bbb, kz_govt, kz_corp

-- Драгметаллы (USD за унцию, конец года)
metals (year INT, metal TEXT, price_usd REAL, PRIMARY KEY(year, metal))
-- metal: gold, silver, platinum

-- Недвижимость Казахстан, $/м², средняя цена за кв.м, конец года
real_estate (year INT, city TEXT, segment TEXT, price_usd_sqm REAL, rental_yield_pct REAL,
             PRIMARY KEY(year, city, segment))
-- city: almaty, astana, shymkent, regional_avg
-- segment: primary, secondary, premium

-- Акции (отдельные тикеры из Fortune 500 + индексы)
equities (year INT, ticker TEXT, name TEXT, sector TEXT,
          price_end_usd REAL, dividend_usd REAL, total_return_pct REAL,
          revenue_usd REAL, employees INT, status TEXT,
          PRIMARY KEY(year, ticker))
-- status: active, delisted, bankrupt, acquired

-- Индексы (для упрощённого пула)
indices (year INT, code TEXT, name TEXT, total_return_pct REAL,
         PRIMARY KEY(year, code))
-- code: SP500, NASDAQ, MSCI_EM, KASE, BLOOM_AGG_BOND

-- Метаданные тикера для Codename Mode
ticker_meta (ticker TEXT PK, founded_year INT,
             hint_short TEXT, hint_full TEXT)

-- Крипто (опционально, с 2010)
crypto (year INT, asset TEXT, price_end_usd REAL, PRIMARY KEY(year, asset))
-- asset: btc, eth (с 2015)
```

### 3.2 Источники данных (реальные, верифицируемые)

| Класс | Источник | Покрытие |
|---|---|---|
| CPI США | FRED `CPIAUCSL` | 1913–наст. |
| CPI Казахстан | stat.gov.kz / Нацбанк РК | 1994–наст. |
| USD/KZT | Нацбанк РК (исторические курсы) | 1993–наст. |
| Fed funds | FRED `FEDFUNDS` | 1954–наст. |
| Базовая ставка НБ РК | nationalbank.kz | 1995–наст. |
| Депозитные ставки KZ | Бюллетени НБ РК (avg по системе) | 2000–наст. (до 2000 — оценка) |
| Treasuries | FRED `DGS1`, `DGS10` | полное покрытие |
| Корпоративные облигации | Moody's Seasoned Aaa/Baa | полное покрытие |
| Золото | LBMA London Fix (год. среднее) | 1968–наст. |
| Серебро/Платина | LBMA | полное покрытие |
| Недвижимость Алматы/Астана | krisha.kz годовые отчёты, stat.gov.kz, аналитика ЦБ КЦДК | 2000–наст. (1996–1999 — оценка через CPI) |
| Fortune 500 акции | Yahoo Finance (yfinance dump), Macrotrends, WSJ Markets historical | 1996–наст. |
| Индексы (SP500, NASDAQ, KASE) | соответствующие биржи | 1996–наст. |
| Биткоин | CoinGecko / Yahoo `BTC-USD` | 2010–наст. |

**Пул акций для игры**: 60–80 тикеров. Принцип отбора: топ-50 Fortune 500 на середину периода (например, 2010 год) + 10–15 «звёзд» (NVDA, AAPL, AMZN, GOOG, MSFT, TSLA) + 10–15 «банкротов» для интриги (Lehman, Enron, GE-era, Nokia, BlackBerry, WeWork, Yahoo, Sears). Banks/Industrial/Tech/Energy/Consumer должны быть представлены **примерно поровну** — иначе Codename Mode выдаст сектор.

### 3.3 Скрипт загрузки

`scripts/build-historical-db.mjs` — отдельная утилита (не часть рантайма). Читает CSV/JSON из `data/sources/` (положенные руками), валидирует, собирает SQLite. Запускается один раз при подготовке к мероприятию или при обновлении данных.

```
data/
  historical.sqlite      ← rebuild артефакт, в git НЕ кладём (gitignore)
  sources/
    fred_cpi.csv
    yfinance_dump.csv
    lbma_gold.csv
    nbrk_rates.csv
    krisha_realestate.json
    ...
```

Альтернатива: коммитим готовую `historical.sqlite` (для воспроизводимости мероприятия). Решение — на этапе реализации.

## 4. Игровой цикл

### 4.1 Фазовая машина (расширение существующей)

Добавляем в `Phase`:

```
idle
  → invest-lobby          // ждём игроков, видны правила и стартовый капитал
  → invest-briefing       // intro к году N: новости, контекст (3–10 сек таймер)
  → invest-trading        // игроки ребалансируют портфель (по умолчанию 90 сек)
  → invest-event-reveal   // раскрытие event card этого года (5–10 сек)
  → invest-results        // раскрытие доходностей, обновление портфелей, leaderboard
  → invest-final          // финал: статистика, призовая церемония, achievements
```

Цикл `briefing → trading → event-reveal → results` повторяется по количеству лет в выбранном диапазоне. После последнего года → `invest-final`.

### 4.2 Что игрок видит на каждой фазе

**Briefing (год N):**
- «Год N. Что происходит в мире» — заголовки новостей (часть фактических, часть alt-history, часть фейков — игрок не знает, что есть что).
- Текущий портфель (структура, $ и ₸ эквивалент).
- Текущая инфляция прогноз (с шумом).
- Доступные «карты стратегий» (см. §7).

**Trading (год N):**
- Слайдеры / поля ввода для перераспределения.
- Constraints: cap на один тикер, max ребаланс 30% за год (настраивается).
- Транзакционные издержки (0.1% для ликвидных, до 5% для недвижимости — реальная цифра).
- Таймер обратного отсчёта.
- Кнопка «зафиксировать ход» (lock-in, нельзя менять после).

**Event Reveal:**
- Анимация переворота карты события (визуальный приём из квиза).
- Эффект ивента на конкретные классы активов (множители).

**Results (год N):**
- Доходность каждого актива за год (раскрыто).
- Обновлённый портфель в $ и ₸.
- Реальная доходность (с учётом инфляции).
- Leaderboard.
- 2 секунды на эмоции → переход к briefing N+1.

**Final:**
- График капитала каждого игрока по годам.
- Win condition cards (см. §9).
- Раскрытие codenames (если режим был включён).
- Список «упущенных возможностей» (что было бы, если…).

## 5. Классы активов и доходности

### 5.1 Поддерживаемые активы

| Класс | Ликвидность | Транз. издержки | Минимальный срок | Доходность из таблицы |
|---|---|---|---|---|
| Кэш USD | мгновенная | 0 | — | 0% (или fed_funds для money market) |
| Кэш KZT | мгновенная | 0 | — | 0% |
| Депозит USD 12м | заперт 1 год | 0 | 1 год | `deposits.rate_pct` |
| Депозит KZT 12м | заперт 1 год | 0 | 1 год | `deposits.rate_pct` |
| Депозит KZT 36м | заперт 3 года | 0 (штраф за досрочный выход −50% начисленных %) | 3 года | `deposits.rate_pct` |
| US Treasuries 10y | ликвидна | 0.1% | — | `bonds` |
| US Corp BBB | ликвидна | 0.3% | — | `bonds` |
| KZ Govt Bonds | средняя | 0.5% | — | `bonds` |
| Акция (тикер) | ликвидна | 0.2% | — | `equities.total_return_pct` |
| Индекс S&P 500 | ликвидна | 0.1% | — | `indices.total_return_pct` |
| Индекс KASE | средняя | 0.5% | — | `indices` |
| Недвижимость Алматы primary | низкая | **5% покупка, 3% продажа** | заперта 2 года минимум | `real_estate` + rental_yield |
| Недвижимость Астана secondary | низкая | 5%/3% | 2 года | `real_estate` |
| Золото | средняя | 1% | — | `metals.gold` |
| Серебро | средняя | 1.5% | — | `metals.silver` |
| Биткоин (с 2010) | ликвидна | 1% | — | `crypto.btc` |

**Учёт инфляции**: портфель отображается в двух представлениях — номинальный и в долларах 1996 года. Финальный счёт по умолчанию в реальных деньгах (с учётом CPI), но опция переключения есть.

**Валютный риск**: USD/KZT берётся из `fx_rates`. Активы в ₸ при оценке портфеля в $ конвертируются по курсу на конец года → девальвации больно бьют по KZT-активам.

### 5.2 Дивиденды и купоны

- Акции: `total_return_pct` уже включает дивиденды (это total return, не price return).
- Облигации: годовой купон = yield × номинал, переоценка по изменению ставок (упрощённо: ±duration × Δyield).
- Недвижимость: годовая аренда = `rental_yield_pct × price`, минус 10% управление, минус амортизация 1.5%.

## 6. Антихиндсайт-механики

### 6.1 Codename Mode (по умолчанию ВКЛ для Hard difficulty)

Тикеры маскируются. Игрок видит:

```
┌────────────────────────────────────┐
│ TECH-07                            │
│ Software, founded 1998             │
│ Revenue $86M, employees 24         │
│ HQ: California                     │
│ Sector: Internet Search            │
│ ★★★☆☆ analyst rating               │
└────────────────────────────────────┘
```

Может быть Google в 2002, может быть Yahoo, может быть Alta Vista. Hint умышленно неоднозначный. Раскрытие — только в `invest-final`.

Хинты генерируются заранее в `ticker_meta.hint_short` / `hint_full` вручную при подготовке датасета.

### 6.2 Alt-History Modifiers

При старте каждой игры случайно выбираются 2–4 модификатора из колоды:

```yaml
- id: "no_iphone"
  description: "В этой реальности Apple так и не выпустил iPhone."
  effect: { ticker: AAPL, years: 2007-2015, multiplier: 0.4 }

- id: "lehman_survives"
  description: "Lehman Brothers получил помощь и пережил 2008."
  effect: { ticker: LEH, years: 2008+, multiplier: 1.0 }
  cascade: { sector: financials, year: 2008, multiplier: 1.15 }

- id: "tenge_super_devalue"
  description: "В 2014 девальвация тенге сильнее реальной."
  effect: { fx_kzt, year: 2014, multiplier: 1.4 }

- id: "gold_disinterest"
  description: "Центробанки массово сбрасывают золото."
  effect: { metal: gold, years: 2000-2010, multiplier: 0.7 }

- id: "kz_realestate_boom_extended"
  description: "Бум недвижимости в Казахстане продлился ещё 2 года."
  effect: { real_estate: almaty, years: 2007-2008, multiplier: 1.3 }

- id: "covid_no_recovery"
  description: "Рынки не отскочили после 2020 так быстро."
  effect: { index: SP500, years: 2020-2021, multiplier: 0.7 }
```

Колода 20–30 модификаторов. Игрокам **не показывается**, какие активны (это часть тумана). Раскрывается в финале.

### 6.3 Concentration Caps & Friction

- Cap на один тикер: **20%** (настраивается админом, можно 100% для безбашенного режима).
- Cap на один сектор: **40%**.
- Max ребаланс за год: **30%** портфеля (защита от моментального all-in / all-out).
- Cooldown на недвижимость: купил — держи 2+ года.

### 6.4 Honeypots (опционально)

В пул тикеров можно подмешать **фиктивные** компании (выглядят правдоподобно: «MEGACOMP — internet ads, $4B revenue, growing 30% yoy» → на самом деле теряет 90% в 2002). Раскрываются в финале. Использовать осторожно: фейки разрушают реализм, лучше использовать вместо них **реальные банкроты** (Enron, Worldcom, Lehman, Bear Stearns, Yahoo, Sears, Nokia, Kodak).

## 7. Карты стратегий (power-ups)

Каждому игроку выдаётся колода ограниченных одноразовых способностей. Использование — слот в UI рядом с портфелем. Стандартная раздача:

| Карта | Кол-во | Эффект |
|---|---|---|
| 🔍 **Insider Brief** | 1 | Раскрывает реальное имя одного актива (снимает Codename) |
| 🛡️ **Hedge** | 2 | После раскрытия результатов: блокирует убыток на одной позиции на 50% (страховка по премиальной цене 2% от позиции, оплачивается вперёд) |
| 📰 **Counter-narrative** | 1 | Помечает одну из новостей briefing'а как фейк |
| 💼 **Short Sell** | 1 | Открыть короткую позицию на 1 тикер на 1 год (макс. 10% портфеля) |
| ⏳ **Skip Year** | 1 | Парковка всего в кэш USD без транзакционных издержек |
| 🔮 **Crystal Ball** | 1 | Подсмотреть event card следующего года заранее |
| 📊 **Analyst Report** | 2 | Получить «честный» рейтинг одного актива на текущий год (точность 80%) |
| 🎲 **Lucky Roll** | 1 | +5% к доходности любой одной позиции в этом году (компенсируется случайным −5% у другого игрока на лидерборде — соревновательная вкладка) |

Карты не накапливаются между играми. Распределение можно менять в админке.

## 8. Event Cards / News Ticker

Колода исторических и фантастических событий. Каждый раунд тянется 1–3 карты. Часть из них реальные (применяются именно в свой год), часть — рандомные («дрейфующие»), часть — фейковые (нет эффекта, но игрок видит).

### 8.1 Реальные «прибитые» события (примеры)

```yaml
- year: 2000
  title: "Dot-com bubble bursts"
  type: real
  effect: { sector: tech, multiplier: 0.6, lasting: 3 years (decay) }

- year: 2001
  title: "9/11 — terror attack on WTC"
  effect: { sector: airlines, multiplier: 0.5; sector: defense, multiplier: 1.2 }

- year: 2008
  title: "Global Financial Crisis"
  effect: { sector: financials, mult: 0.4; sector: real_estate_us, mult: 0.55; index: SP500, mult: 0.62 }

- year: 2014
  title: "Тенге девальвируется на 19% за день"
  effect: { fx: usd_kzt, mult: 1.19 (single shock) }

- year: 2015
  title: "Свободное плавание тенге"
  effect: { fx: usd_kzt, mult: 1.85 (over year) }

- year: 2020
  title: "COVID-19 пандемия"
  effect: { sector: tech, mult: 1.4; sector: airlines, mult: 0.4; sector: energy, mult: 0.7 }

- year: 2022
  title: "Война в Украине"
  effect: { commodity: oil, mult: 1.45; sector: defense, mult: 1.3; ru_assets: blocked }
```

### 8.2 Дрейфующие (могут случиться в любой год периода)

```yaml
- title: "Сбой энергосети в крупном городе"
  effect: { sector: utilities, mult: 0.85 }

- title: "Прорыв в биотехнологиях"
  effect: { sector: pharma, mult: 1.25 }

- title: "Регулятор ужесточает требования к банкам"
  effect: { sector: financials, mult: 0.92 }
```

### 8.3 Фейковые

Не имеют эффекта, но звучат правдоподобно. Используются для шума. Counter-narrative карта раскрывает их.

## 9. Условия победы (multi-winner)

Каждая игра присваивает несколько «титулов». Один игрок может взять несколько.

| Титул | Метрика | Иконка |
|---|---|---|
| 🥇 **Капиталист года** | Максимальный финальный nominal balance | gold |
| 💎 **Реальный мастер** | Максимальный финальный inflation-adjusted balance | diamond |
| ⚖️ **Хладнокровный** | Лучший Sharpe-подобный score (return / volatility по годам) | scales |
| 🛡️ **Стойкий** | Минимальная максимальная просадка (max drawdown) | shield |
| 🌈 **Диверсификатор** | Самый высокий средний HHI-обратный по портфелю | rainbow |
| 🚀 **Бык** | Лучший один отдельный год | rocket |
| 🐻 **Антикризис** | Лучший результат в худший год периода | bear |
| 🎯 **Снайпер** | Самый высокий ROI на удачную ставку (>5x на одной позиции) | target |
| 🍀 **Везунчик** | Самый высокий результат среди тех, кто использовал Lucky Roll | clover |

Призовая церемония в `invest-final` показывает все титулы поочерёдно с анимацией.

## 10. Архитектура (как ложится в текущий код)

### 10.1 Новые модули сервера

```
server/src/
  index.ts                    ← существует, добавляем invest-* фазы
  invest/
    historicalDb.ts           ← read-only sqlite3 wrapper
    gameEngine.ts              ← state machine, расчёты доходностей
    eventDeck.ts               ← event cards, shuffling
    altHistory.ts              ← модификаторы
    codenames.ts               ← маскирование тикеров
    types.ts                   ← Investment-specific types
```

### 10.2 Новые типы

```typescript
type InvestPhase =
  | 'invest-lobby'
  | 'invest-briefing'
  | 'invest-trading'
  | 'invest-event-reveal'
  | 'invest-results'
  | 'invest-final';

interface InvestmentGame {
  startYear: number;
  endYear: number;
  currentYear: number;
  difficulty: 'easy' | 'normal' | 'hard';
  codenameMode: boolean;
  altHistoryModifiers: AltHistoryModifier[];   // выбранные для этой партии
  allowedAssets: AssetId[];
  config: {
    startUsd: number;       // 100_000
    startKzt: number;       // 10_000_000
    capPerTicker: number;   // 0.20
    capPerSector: number;   // 0.40
    maxRebalancePct: number;// 0.30
    tradingSecondsPerYear: number; // 90
    powerups: PowerupAllocation;
  };
  eventDeck: EventCard[];
  resolvedEvents: Record<number, EventCard[]>; // year → выпавшие карты
}

interface Portfolio {
  positions: Record<AssetId, number>;   // units / shares / $ для кэша
  cashUsd: number;
  cashKzt: number;
  lockedUntil: Record<AssetId, number>; // year, до которого нельзя продать
  powerupsUsed: string[];
  history: YearSnapshot[];              // для графика
}

interface YearSnapshot {
  year: number;
  totalUsd: number;
  totalKztEquiv: number;
  realUsd: number;        // inflation-adjusted
  allocation: Record<AssetId, number>;  // % shares
  yearReturn: number;
  events: string[];       // ids of events that hit them
}

interface PlayerInvestState {
  participantId: string;
  portfolio: Portfolio;
  pendingOrder?: TradingOrder;  // что игрок зафиксировал в trading фазе
  powerupsAvailable: Record<string, number>;
  achievements: string[];
}
```

### 10.3 Хранение

- **Историческая БД**: `data/historical.sqlite` (read-only, не пишем).
- **Сохранённые конфиги игр**: `data/investment-games.json` (по аналогии с `quiz-rounds.json`) — пресеты, которые админ хочет переиспользовать.
- **Активный стейт игры**: только в RAM, обнуляется при рестарте — как и квиз.

### 10.4 Сокет-события

```
// Сервер → клиент (admin)
admin:invest-state         // полный стейт игры + всех игроков

// Сервер → клиент (player)
player:invest-state        // персональный стейт (свой портфель, доступные действия)
player:invest-briefing     // raw briefing payload (новости, текст)
player:invest-results      // результаты года

// Клиент → сервер (admin)
admin:invest-create        // создать игру (start/end, difficulty, allowedAssets)
admin:invest-start         // запуск из лобби
admin:invest-next-phase    // ручной шаг (для модератора)
admin:invest-reveal-codename
admin:invest-end-early

// Клиент → сервер (player)
player:invest-place-order  // зафиксировать ребаланс
player:invest-use-powerup
```

### 10.5 Где ломается single-emit инвариант

В CLAUDE.md прописано: «всегда вызывать `emitState()` после мутаций». Для invest нужно либо:
- расширить `emitState` чтобы он эмитил и квизовый, и инвестовый стейт (зависит от `phase`),
- либо ввести второй emit-канал `emitInvestState()` и вызывать его строго после любой мутации `InvestmentGame` или `PlayerInvestState`.

**Рекомендация**: второй вариант. Один файл `invest/emit.ts`, единственная функция, везде вызываемая. По образцу существующего `emitState`.

### 10.6 Что НЕ трогать

- Викторину. Это параллельная игра, переключение через `phase` на верхнем уровне.
- Систему авторизации (`assertAdmin`, токен).
- Проверку никнеймов (`normalizeNickname`, `isTooSimilar`).
- Лимиты body/socket (80mb / 100mb) — для invest не нужно.

## 11. UI / экраны клиента

### 11.1 Player экраны

## 12. Балансировка и тестирование

### 12.1 Backtests до выпуска

Прогнать тестовый прогон для каждого periodа продолжительностью ≥ 5 лет с дефолтной конфигурацией:

| Стратегия | Ожидаемый результат |
|---|---|
| 100% в S&P 500 | Должна быть конкурентоспособна, но не доминировать (5/9 побед). |
| 100% в Apple/Google (если codename выключен) | Должна побеждать без alt-history — НО с alt-history часто проигрывать. |
| 60/40 stocks/bonds | Стабильный survivor — обычно берёт «Стойкого» и «Хладнокровного». |
| Только золото | Хороший шанс на 2000s, плохой на 2010s. |
| Только KZT депозит | Жестоко наказывается в 2014/2015/2022. |
| Случайный аллокатор (бот) | Среднее по больнице, должен быть baseline. |

Если какая-то стратегия выигрывает >70% прогонов — крутим ручки (cap, alt-history веса, transaction costs).

### 12.2 E2E сценарий

По образцу `scripts/e2e-full.mjs` создать `scripts/invest-e2e.mjs`:
- Поднимает игру на 5 лет.
- Подключает N=30 фейковых игроков с разными стратегиями (random, all-equity, conservative, gold-bug).
- Гоняет полный цикл.
- Проверяет инварианты: сумма ребаланса ≤ portfolio, нет negative balance, локи соблюдаются, расчёт инфляции корректен.

### 12.3 Производительность

С 100 игроками × 30 лет × N активов: расчёт всё ещё mike-grade (миллисекунды). Узких мест нет, но `emitInvestState` к 100 игрокам — нужно проверить через webhook-like микробенчмарк, если будет тормоз — батчить через `for...of` без `await`.

## 14. Расширения для v2

Не обязательны для запуска, но стоит заложить хуки в архитектуре:

- **Командный режим** — 2–4 игрока в одной «фирме» с общим портфелем, голосование за решения.
- **Маржинальное плечо** с риском маржин-колла.
- **Опционы** (calls/puts) на индексы — для продвинутых.
- **PvP-аукционы** — на лимитированные активы (например, единичная элитная недвижимость, выкупается через аукцион в реальном времени).
- **Криптотрек** как отдельный режим с 2010 года.
- **Кастомные «что если» сценарии** — модератор пишет свои alt-history карты перед игрой.
- **Социальные механики** — игроки могут давать друг другу «советы» (бесплатно неточные, за плату точные).
- **Турнирные сетки** — несколько серий по 5 лет, накопительный счёт.

## 15. Открытые вопросы (для согласования)

1. **Codename mode по умолчанию on или off?** Я предлагаю on для Hard, off для Easy.
2. **Биткоин — включать?** С 2010 — да, но искажает баланс в пользу того, кто угадает (хотя alt-history может это нивелировать).
3. **Капитал в обеих валютах или только USD?** Я заложил оба — добавляет валютный риск как механику. Можно ужать до одного USD для простоты.
4. **Где хранить датасет в Docker-образе?** Если коммитим `historical.sqlite` — нужно либо включить в образ (увеличивает размер MB на 5–20), либо положить через bind-mount как `data/quiz-rounds.json`. Рекомендую bind-mount + опционально пред-собранный образ.
5. **Длина игры**. 30 лет × 90 сек = 45 минут только торговли. С briefing/events/results реально 70–90 минут. Это слишком долго для очной игры? Возможно стоит дефолтить на 10–15 лет.
6. **Названия**. «Time Capital», «Hindsight Hedge», «Capital Time Trial», «Tenge & Dollar», «Vibe Invest» — нужно выбрать.

## 16. TL;DR для модератора

Игра — это «викторина, только про деньги и историю». Длится час, у каждого игрока на руках виртуальные $100K и ₸10М, нужно пережить 10–30 лет реальной истории и не разориться. Чтобы никто не выигрывал заучиванием — компании скрыты, реальность каждый раз чуть другая, портфель нельзя слить в одну акцию, и события случаются непредсказуемо. Побеждает не один человек, а несколько — кто заработал больше всех, кто меньше всех просел, кто лучше всех держал баланс. Веселье — за счёт новостей, событий, карт стратегий и финального раскрытия «а это был Google, прикинь».
